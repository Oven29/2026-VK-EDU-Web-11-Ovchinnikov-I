# Отчет по нагрузочному тестированию Nginx и Gunicorn

## 1. Сводные результаты тестирования

| Тип теста | Requests per second (RPS) | Time per request (mean) |
| :--- | :--- | :--- |
| **1. Статика через Nginx** | 9330.75 | 10.717 ms |
| **2. Статика через Gunicorn** | 2729.05 | 36.643 ms |
| **3. Динамика через Gunicorn (напрямую)** | 2335.19 | 42.823 ms |
| **4. Динамика через Nginx (БЕЗ кэша)** | 2638.63 | 37.898 ms |
| **5. Динамика через Nginx (С proxy_cache)** | 7380.10 | 13.550 ms |

---

## 2. Анализ производительности

### Насколько быстрее отдается статика через Nginx по сравнению с Gunicorn?
Согласно результатам тестов, Nginx отдает статические файлы значительно эффективнее. 
- RPS Nginx: **9330.75**
- RPS Gunicorn: **2729.05**

**Математический расчет:**  
$9330.75 / 2729.05 \approx \mathbf{3.42}$

**Вывод:** Статика через Nginx отдается в **3.42 раза быстрее**, чем через Gunicorn. Это связано с тем, что Nginx оптимизирован для асинхронной работы с файловой системой на низком уровне, в то время как Gunicorn (WSGI) несет накладные расходы на интерпретацию Python-кода даже для простых задач.

### Во сколько раз proxy_cache ускоряет обработку динамических запросов?
Кэширование на стороне Nginx позволяет избежать обращения к серверу приложений для повторяющихся запросов.
- RPS Nginx с кэшем: **7380.10**
- RPS Nginx без кэша: **2638.63**

**Математический расчет:**  
$7380.10 / 2638.63 \approx \mathbf{2.80}$

**Вывод:** Использование `proxy_cache` ускоряет работу приложения в **2.8 раза**. Это практически приближает скорость отдачи динамического контента к скорости чистой статики, так как Nginx отдает закэшированный ответ из оперативной памяти/диска, не дожидаясь выполнения логики в Gunicorn/Django.

---

## 3. Итоговый вывод

На основе проведенных тестов можно четко определить роль **Nginx** в архитектуре высоконагруженного веб-приложения:

1.  **Снятие нагрузки с бэкенда:** Nginx должен брать на себя всю работу со статикой (изображения, стили, скрипты), освобождая воркеры Gunicorn для выполнения бизнес-логики.
2.  **Эффективное кэширование:** Использование `proxy_cache` позволяет на порядок снизить нагрузку на бэкенд и базу данных для часто запрашиваемых страниц, обеспечивая время отклика, сопоставимое со статическими файлами.
3.  **Оптимизация соединений:** Nginx эффективнее управляет очередями запросов и медленными клиентами, выступая защитным буфером перед сервером приложений.

Без Nginx приложение теряет более 70% своей потенциальной пропускной способности.
